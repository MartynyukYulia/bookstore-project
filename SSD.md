# SYSTEM SPECIFICATION DOCUMENT (SSD)

## 1. Мета та обсяг (Purpose and Scope)

- **Обґрунтування проблеми:** Малі книгарні та видавництва не мають доступного інструменту для організації онлайн-продажів. Відсутність веб-платформи означає обмеженість фізичним розташуванням магазину, ручний облік залишків та неможливість цілодобового обслуговування покупців.
- **Мета системи:** Розробка та впровадження веб-застосунку «Інтернет-магазин книг» на PHP 8 та MySQL, що охоплює повний цикл взаємодії: від публічного перегляду каталогу з фільтрацією до оформлення замовлень через транзакції бази даних, особистого кабінету покупця та адміністративної панелі управління контентом.
- **Технологічний стек:** Backend — PHP 8 без фреймворків, СУБД — MySQL 8 з рушієм InnoDB, інтерфейс до БД — PDO з підготовленими запитами, Frontend — HTML5, CSS3, JavaScript ES6+ з Fetch API, веб-сервер — Apache 2.4 (XAMPP).

## 2. Функціональні вимоги (Functional Requirements)

### 2.1. Склад виконуваних функцій

Система забезпечує автоматизацію наступних процесів:

1. Перегляд каталогу книг з відображенням карток (назва, автор, ціна, обкладинка, наявність).
2. Детальний перегляд окремої книги (повний опис, категорія, залишок на складі, кнопка додавання до кошика).
3. Розширена фільтрація списку книг за категорією через GET-параметр `cat` та текстовий пошук за назвою і автором через GET-параметр `search` з LIKE-запитом у PDO.
4. Пагінація каталогу по 12 записів на сторінку через LIMIT/OFFSET у SQL-запиті.
5. Реєстрація нових користувачів з валідацією на сервері (унікальність логіна та email, мінімальна довжина пароля, збіг паролів) та хешуванням через `password_hash(PASSWORD_DEFAULT)`.
6. Авторизація у двох режимах: стандартна форма з перезавантаженням сторінки та асинхронна через AJAX-запит до `login_ajax.php` з JSON-відповіддю.
7. Управління кошиком через AJAX-ендпоінт `cart_action.php`: додавання (`action: add`), зміна кількості (`action: update`), видалення позиції (`action: remove`). Всі операції без перезавантаження сторінки.
8. Динамічний лічильник кошика в навігаційній панелі через окремий ендпоінт `cart_count.php`.
9. Оформлення замовлення через POST-запит з `checkout=1`: виконується у рамках транзакції БД (INSERT orders → INSERT order_items → UPDATE books SET stock → DELETE cart → COMMIT, або ROLLBACK при помилці).
10. Перегляд покупцем власних замовлень на `my_orders.php` та асинхронне завантаження деталей позицій через `order_details.php`.
11. Адміністративна панель (CMS) з повним CRUD для книг, категорій, новин, користувачів та управління замовленнями зі зміною статусів.
12. Централізований ендпоінт видалення `admin/delete.php` з whitelist-масивом дозволених SQL-операцій на сервері.

### 2.2. Сценарії використання (User Stories) за ролями

**Незареєстрований відвідувач:**
- Як відвідувач, я можу переглядати каталог книг та застосовувати фільтри за категорією та пошуком, щоб знайти потрібну книгу.
- Як відвідувач, я можу відкрити детальну картку книги, щоб дізнатися повний опис, ціну та наявність на складі.
- Як відвідувач, я можу читати новини магазину, щоб дізнатися про акції.
- Як відвідувач, я можу зареєструватися, вказавши логін, email та пароль, щоб отримати доступ до кошика та замовлень.

**Зареєстрований користувач:**
- Як користувач, я можу авторизуватися через форму або AJAX без перезавантаження сторінки, щоб увійти до особистого кабінету.
- Як користувач, я можу додавати книги до кошика асинхронно з будь-якої сторінки каталогу, щоб формувати список покупок.
- Як користувач, я можу змінювати кількість товарів у кошику та видаляти окремі позиції через AJAX без перезавантаження.
- Як користувач, я можу оформити замовлення одним натисканням, після чого залишки на складі зменшуються автоматично, а кошик очищується.
- Як користувач, я можу переглядати список своїх замовлень та відстежувати їх статус у реальному часі.
- Як користувач, я можу асинхронно переглянути деталі замовлення (список книг із кількістю та цінами на момент покупки) без переходу на нову сторінку.

**Адміністратор:**
- Як адміністратор, я можу додавати нові книги до каталогу через форму з live-preview обкладинки, редагувати їхні дані та видаляти їх асинхронно.
- Як адміністратор, я можу керувати категоріями книг: створювати, перейменовувати та видаляти. При видаленні категорії книги залишаються в системі з `category_id = NULL`.
- Як адміністратор, я можу переглядати всі замовлення від користувачів та змінювати їхні статуси (pending → processing → completed / cancelled) через select безпосередньо в таблиці.
- Як адміністратор, я можу публікувати, редагувати та видаляти новини магазину.
- Як адміністратор, я можу переглядати список усіх користувачів, змінювати їхні ролі між `user` та `admin` та видаляти облікові записи, але не можу видалити власний акаунт.

## 3. Нефункціональні вимоги (Non-Functional Requirements)

### 3.1. Продуктивність (Performance)

- **Час реакції інтерфейсу:** Час реакції системи на базові дії користувача не повинен перевищувати 0,25 секунди.
- **Час завантаження сторінок:** Сторінки каталогу, головна та картка книги — не більше 1 секунди.
- **Час відповіді AJAX-ендпоінтів:** Ендпоінти `cart_action.php`, `cart_count.php`, `order_details.php` — не більше 0,5 секунди.
- **Відображення масивів даних:** Пагінація через SQL LIMIT/OFFSET по 12 записів на сторінку запобігає перевантаженню пам'яті сервера та клієнта при великому обсязі каталогу.
- **Системні ресурси:** Мінімальний обсяг оперативної пам'яті сервера — 512 МБ. Обсяг дискового простору для коду та дампу бази даних — не більше 50 МБ.

### 3.2. Безпека (Security)

- **Захист від SQL-ін'єкцій:** Всі запити до бази даних виконуються виключно через PDO підготовлені вирази (`$pdo->prepare($sql)->execute($params)`) з вимкненою емуляцією (`PDO::ATTR_EMULATE_PREPARES => false`). Жоден користувацький ввід не підставляється безпосередньо в SQL-рядок.
- **Захист від XSS:** Весь вивід користувацьких даних у HTML-шаблонах екранується через `htmlspecialchars()`.
- **Криптографічний захист паролів:** Паролі зберігаються у вигляді bcrypt-хешу через `password_hash($password, PASSWORD_DEFAULT)`. Перевірка при вході — через `password_verify($input, $hash)`. Відкритий текст паролю ніколи не зберігається.
- **Рольова модель доступу (RBAC):** Кожен захищений PHP-файл починається з виклику `requireLogin()` або `requireAdmin()` з файлу `includes/auth.php`. Ці функції перевіряють `$_SESSION['user_id']` та `$_SESSION['role']` на стороні сервера незалежно від клієнтського інтерфейсу. При невідповідності — негайний `header('Location: ...')` redirect.
- **Захист від фіксації сесії:** Після успішного входу викликається `session_regenerate_id(true)`, що генерує новий ID сесії.
- **Whitelist-захист ендпоінту видалення:** В `admin/delete.php` список допустимих SQL-операцій визначено статично у масиві `$allowed` на сервері. Клієнт передає лише тип сутності (`book`, `user`, `news`, `category`, `order`), але не може впливати на SQL-запит.

### 3.3. Масштабованість (Scalability)

- **Модульна архітектура:** Система організована за модульним принципом: `modules/books/`, `modules/orders/`, `modules/news/`, `admin/`, `includes/`. Додавання нового модуля не потребує змін у наявному коді.
- **Розширюваність бази даних:** Структура БД нормалізована (3NF). Зовнішні ключі визначені з правилами каскадування — `ON DELETE CASCADE` для `order_items` та `cart`, `ON DELETE SET NULL` для `books.category_id` та `orders.user_id`.

## 4. Інтерфейси (Interfaces)

- **Тип архітектури:** Класична клієнт-серверна модель. Apache обробляє HTTP-запити та передає їх PHP-інтерпретатору. Для звичайних сторінок сервер повертає згенерований HTML, для AJAX-запитів — JSON з заголовком `Content-Type: application/json`.
- **Клієнт-серверні інтерфейси:** Стандартні HTTP GET/POST запити через HTML5-форми для звичайних сторінок. Асинхронні запити через `fetch()` з JavaScript для операцій з кошиком, авторизацією та адмін-панеллю. Дані передаються у тілі запиту як JSON та зчитуються через `json_decode(file_get_contents('php://input'), true)`.
- **JSON API ендпоінти:**
  - `login_ajax.php` — POST `{username, password}` → `{success, message?}`
  - `modules/orders/cart_action.php` — POST `{action, book_id, quantity?}` → `{success, message?}`
  - `modules/orders/cart_count.php` — GET → `{count: N}`
  - `modules/orders/order_details.php` — GET `?id=N` → `[{title, quantity, price}]`
  - `admin/delete.php` — POST `{id}` + GET `?type=...` → `{success, message?}`
- **Зовнішні інтерфейси:** Завантаження зображень обкладинок книг за URL із поля `cover_url` таблиці `books` виконується браузером клієнта через тег `<img src="...">`. Атрибут `onerror` забезпечує відображення CSS градієнтної заглушки при недоступності зовнішнього URL.

## 5. Обмеження (Constraints)

- **Технологічний стек:**
  - *Backend:* PHP 8 без фреймворків (Laravel, Symfony заборонені умовами завдання). Взаємодія з БД — виключно через PDO.
  - *Database:* MySQL 8 з рушієм InnoDB, кодування `utf8mb4_unicode_ci`.
  - *Frontend:* HTML5, CSS3, чистий JavaScript ES6+ (jQuery та інші бібліотеки не використовуються).
  - *Середовище:* Локальний XAMPP (Apache + MySQL + PHP). IDE — VS Code або PhpStorm.
- **Архітектурні обмеження:** Система реалізована без повноцінного патерну MVC відповідно до вимог навчального завдання. Застосунок є монолітним — всі модулі в одному проєкті.
- **Бюджет:** Проєкт розроблено як некомерційне програмне забезпечення в рамках курсової роботи. Використано виключно безкоштовні технології з відкритим вихідним кодом.
- **Регулятивні обмеження:** База даних зберігає персональні дані користувачів (логін, email, хеш пароля). Система забезпечує конфіденційність через захист від несанкціонованого доступу. Користувач має право на видалення свого облікового запису адміністратором.
