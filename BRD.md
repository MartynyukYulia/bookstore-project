# BUSINESS REQUIREMENTS DOCUMENT (BRD)

## 1. Вступ (Introduction)

- **Мета документа:** Цей документ описує бізнес-вимоги до розробки веб-сайту «Інтернет-магазин книг». Він визначає основні бізнес-цілі, цільову аудиторію та очікувану цінність від впровадження продукту.
- **Бізнес-ціль (Business Goal):** Вирішення проблеми відсутності зручного онлайн-каналу продажу книг для малих книгарень та видавництв. Створення платформи, яка дозволить автоматизувати процес пошуку книг для покупців, організувати облік замовлень та залишків товарів, а також надати власнику магазину повний контроль над керуванням контентом без залучення технічних спеціалістів.

## 2. Опис предметної області (Business Context)

Ринок онлайн-продажу книг в Україні представлений великими платформами (Yakaboo, Book24, Rozetka), однак малі видавництва та приватні книгарні не мають доступних рішень для самостійного виходу в онлайн. Традиційна торгівля книгами обмежена фізичним розташуванням магазину, годинами роботи та ручним обліком залишків і замовлень. Відсутність власної онлайн-платформи означає втрату покупців, які надають перевагу інтернет-покупкам, неможливість цілодобового обслуговування та відсутність структурованого обліку клієнтської бази.

Аналіз існуючих рішень показує, що великі маркетплейси не зосереджені на специфічних потребах книжкового ринку: відсутня зручна навігація за жанрами та авторами, немає тематичних добірок. Наявність власної системи керування контентом дозволить магазину бути незалежним від сторонніх платформ та гнучко керувати своїми процесами.

## 3. Цільова аудиторія та Ролі (Stakeholders & User Roles)

- **Незареєстровані відвідувачі (Гості):** Потенційні покупці, які хочуть переглянути асортимент книг, дізнатися про ціни та акції без необхідності реєстрації.
- **Зареєстровані покупці (Користувачі):** Клієнти магазину, які хочуть обирати книги, формувати список покупок та оформлювати замовлення з можливістю відстежувати їх стан.
- **Адміністратор магазину:** Власник або менеджер, який відповідає за наповнення каталогу, обробку замовлень та інформування покупців через новини. Потребує зручного інструменту управління без знань програмування.

## 4. Конкурентні переваги (Competitive Advantages)

На основі аналізу існуючих рішень у системі закладено наступні переваги:

- **Спеціалізація:** На відміну від великих маркетплейсів, система повністю зосереджена на книжковому ринку, що дозволяє забезпечити зручну навігацію за жанрами та авторами.
- **Зручний інтерфейс:** Операції з кошиком виконуються без перезавантаження сторінки, що забезпечує швидкий та комфортний процес покупки.
- **Власна панель управління:** Адміністратор повністю контролює контент через веб-інтерфейс без залежності від сторонніх платформ.
- **Надійність замовлень:** Система гарантує, що при оформленні замовлення дані або зберігаються повністю, або не зберігаються взагалі — часткових або суперечливих станів не виникає.

## 5. Межі проєкту (Project Scope)

### 5.1. Що входить у проєкт (In-Scope)

- Публічний каталог книг із системою фільтрації та пошуку.
- Система реєстрації та особистих кабінетів користувачів.
- Модуль кошика та оформлення замовлень.
- Відстеження статусів замовлень для покупців.
- Система новин та акцій магазину.
- Комплексна адміністративна панель для керування всіма сутностями сайту.

### 5.2. Що НЕ входить у проєкт (Out-of-Scope)

- **Фінансові транзакції:** Система не обробляє реальні платежі через інтегровані платіжні шлюзи. Замовлення фіксуються без проведення оплати.
- **Email-нотифікації:** Автоматичне надсилання повідомлень покупцям при зміні статусу замовлення не реалізовано.
- **Система відгуків:** Відсутній модуль оцінок та рецензій книг від покупців.
- **Нативний мобільний додаток:** Доступ з мобільних пристроїв забезпечується через веб-браузер; окремі додатки для iOS/Android не розробляються.
- **Завантаження файлів:** Зображення обкладинок зберігаються як посилання на зовнішні ресурси, завантаження файлів на сервер не передбачено.

## 6. Високорівневі функціональні вимоги (High-Level Functional Requirements)

1. Система повинна дозволяти відвідувачам переглядати каталог книг та шукати потрібний товар без необхідності реєстрації.
2. Система повинна дозволяти новим відвідувачам реєструватися, а наявним — авторизуватися.
3. Система повинна забезпечувати авторизованим покупцям управління кошиком: додавання книг, зміну кількості та видалення позицій.
4. Система повинна дозволяти покупцю оформити замовлення, яке автоматично фіксує перелік книг, ціни та зменшує залишки на складі.
5. Система повинна надавати покупцям доступ до історії власних замовлень з деталями та поточними статусами.
6. Система повинна містити адміністративну панель для управління книгами, категоріями, новинами, користувачами та замовленнями.

## 7. Нефункціональні бізнес-вимоги

- **Зручність використання:** Основні сценарії (пошук книги, додавання до кошика, оформлення замовлення) повинні виконуватися не більше ніж у п'ять кроків. Інтерфейс повністю україномовний та зрозумілий без інструкцій.
- **Надійність даних:** Система не допускає часткового збереження даних при оформленні замовлення. При будь-якій помилці стан даних повертається до вихідного.
- **Безпека:** Особисті дані користувачів зберігаються захищено. Доступ до адміністративних функцій мають лише уповноважені особи.
- **Доступність:** Система доступна через стандартний браузер без встановлення додаткового програмного забезпечення цілодобово.

## 8. Критерії успішності проєкту

- Покупець може знайти книгу, додати її до кошика та оформити замовлення без допомоги персоналу.
- Адміністратор може додавати, редагувати та видаляти книги, категорії та новини через веб-інтерфейс.
- При оформленні замовлення залишки книг на складі зменшуються автоматично.
- Доступ до адмін-панелі захищений — звичайний користувач не може потрапити туди навіть за прямим посиланням.
- Система коректно відображається у сучасних браузерах (Chrome, Firefox, Edge, Safari).
